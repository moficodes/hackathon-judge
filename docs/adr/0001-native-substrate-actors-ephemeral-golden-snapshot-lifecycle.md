# 0001. Native Agent Substrate Actors with Ephemeral Golden-Snapshot Lifecycle

We replace `kubernetes-sigs/agent-sandbox` (`SandboxTemplate`, `SandboxWarmPool`, `SandboxClaim`, and `sandbox-router`) directly with native Agent Substrate `v1.0.0` primitives (`WorkerPool`, `ActorTemplate` with `SNAPSHOT_FIDELITY_MEMORY` Golden Snapshots, and `atenet-router`) rather than layering `agent-substrate/env` or `google/ax` on top. For each Judging Task, the Judge Orchestrator creates a fresh Judge Actor (`judge-<task_id>`) from the Golden Snapshot, drives `/upload`, `/execute`, and `/download` over `atenet-router`, and deletes the Judge Actor (`DeleteActor`) in `finally`—giving ~1–2s warm startup from memory without maintaining idle standby pods, risking cross-task state leakage, or incurring 30–60s Kubernetes pod replacement churn after each evaluation.
